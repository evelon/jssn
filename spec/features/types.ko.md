# 타입

> **JSON Schema 대응:** `type` 키워드. 복합 타입은 이 위에 자신만의 키워드를 추가로 사용합니다 — 아래의 배열, 객체 하위 섹션을 참고하세요.

## 타입 이름

JSON에는 `string`, `number`, `boolean`, `object`, `array`, `null`이라는 여섯 가지 기본 데이터 타입이 있습니다.

JSON Schema는 `type` 키워드에 이 용어들을 그대로 재사용하며, 검증에 사용되는 `number`의 하위 타입으로 `integer`를 일곱 번째 타입으로 추가합니다.

JSSN은 대부분 아래와 같이 이 타입들에 더 짧은 별칭을 사용합니다:

- `string` -> `str`
- `number` -> `num`
- `integer` -> `int`
- `boolean` -> `bool`
- `object` -> `obj`
- `array` -> `arr`
- `null` -> `null` (변경 없음; 이미 짧습니다)
- `any` — JSSN에만 있는 특수한 타입으로, JSON Schema에 대응하는 요소가 없습니다 (아래 참고)

## 사용법

`arr`과 `obj` 두 타입은 복합 타입입니다 — 내부에 다른 타입을 담을 수 있습니다.
`arr`을 작성하려면 대괄호를 사용하세요. `arr`에 타입이 지정된 요소가 있다면 해당 타입들을 나열하기만 하면 됩니다.
`obj`를 작성하려면 중괄호를 사용하세요. `obj`에 속성이 있다면 키 이름을 따옴표 없이 쓰고, 콜론(`:`)과 타입을 이어서 씁니다.

한 줄에 작성할 때는 요소나 속성을 쉼표(`,`)로 구분합니다. 여러 줄에 걸쳐 작성할 때는 줄바꿈만으로도 구분하기에 충분합니다.

### 배열

> **JSON Schema 대응:** `prefixItems`(위치 기반/튜플 검증을 위한 스키마 배열)와 추가 요소를 금지하는 `items: false`의 조합. Draft 7 / 2019-09에서는 동일한 내용을 `items`에 스키마 배열을 주고, `items: false` 대신 `additionalItems: false`를 사용해 작성합니다.

```jssn
[int, bool, str]
```

또는

```jssn
[
  int
  bool
  str
]
```

배열 타입의 items 관련 키워드(요소 타입 제약, 추가 요소 허용 여부 등)에 대한 전체 명세는 [array.ko.md](array.ko.md)를 참고하세요.

### 객체

> **JSON Schema 대응:** `properties` 키워드

```jssn
{one: int, two: int}
```

또는

```jssn
{
  one: int
  two: int
}
```

배열이나 객체 내부에 아무것도 지정하지 않는다면, 다른 타입과 마찬가지로 `arr`이나 `obj` 키워드를 사용하세요.

```jssn
{
  hello: arr
  world: obj
}
```

이 목적으로 빈 `[]`나 `{}`를 사용하지 마세요 — 이들은 빈 배열이나 빈 객체처럼 보이고, 실제로도 그런 의미입니다.

```jssn
{
  hello: []
  world: {}
}
```

### 중첩된 배열 또는 객체

중첩된 배열이나 객체를 작성하려면, 마치 하나의 타입인 것처럼 — 즉 타입이 와야 할 자리에 그대로 — 작성하면 됩니다.

```jssn
[
  int
  {
    hello: str
    world: num
  }
]
```

```jssn
{
  title: str
  author: str
  content: [str, int, num]
}
```

## `any` 타입

위의 별칭들과 달리, `any`는 JSON Schema의 `type` 값 중 하나가 아닙니다 — 아무런 타입 제약이 없음을 의미하며, JSON Schema에서 `type`을 생략하는 것(또는 빈 스키마 `{}`를 사용하는 것)과 동등합니다. `null`을 포함한 모든 타입의 값이 `any`를 만족합니다. 다만 실제로는 `any`를 명시적으로 쓰는 경우가 드뭅니다 — 대부분의 경우, 타입을 그냥 생략하는 것만으로도 같은 의미를 충분히 표현할 수 있습니다.

```jssn
{
  title: str
  description: str
  content
}
```

다만 배열 내부에서는 이것이 성립하지 않습니다: 어떤 자리가 단순히 아무 제약 없는 위치 — 오직 `any`뿐인 자리 — 라면, 여전히 명시적으로 작성해야 합니다:

```jssn
[str, any]
```

여기서 생략하면 쉼표 옆에 빈 자리(`[str, ]`)가 남게 되어, 뒤에 붙은 불필요한 쉼표처럼 읽히고 배열의 요소 개수를 모호하게 만듭니다.

### 설계 노트

- **단순한 생략이 아니라 전용 타입입니다.** JSON Schema는 "제약 없음"을 `type`을 아예 생략하는 것(또는 빈 스키마 `{}`)으로 표현합니다. JSSN은 대신 이 개념에 `any`라는 명시적인 이름을 부여해, 직접 이름 붙이고 다룰 수 있도록 합니다. (위에서 본 것처럼) `any`라는 _단어_ 자체를 종종 생략할 수 있다는 사실이 이를 바꾸지는 않습니다 — 타입 자체는 여전히 일급 개념으로 남아 있고, 그 표기만 때때로 선택적일 뿐입니다.
- **경계가 모호하지 않은 곳에서만 생략 가능합니다.** `any`를 생략하는 것은 타입이 와야 할 자리를 이미 다른 무언가가 표시해주고 있다는 사실에 의존합니다. 객체 속성에서는 콜론(또는 그 부재)이 그 역할을 합니다. 배열의 한 자리에는 그런 표시가 없습니다 — 이웃 요소와 구분해주는 것은 오직 쉼표뿐이며, 쉼표 옆의 빈 자리는 뒤에 붙은 불필요한 쉼표처럼 읽힙니다. 그래서 이 생략은 속성에서는 작동하지만 배열 내부에서는 작동하지 않습니다.
- **`null`을 포함합니다.** `any`는 아무런 제약도 두지 않으므로 `null`도 허용합니다 — 이는 JSON Schema의 빈 스키마 동작과 일치하며, 향후 도입될 수 있는 "null이 아닌 임의 타입" 유니온과는 다릅니다.
- **properties 없이 required인 엣지 케이스를 위해 추가되었습니다.** JSON Schema는 `properties`에 전혀 나타나지 않는 키를 `required`에 나열하는 것을 허용하며, 이 경우 값에는 아무 제약이 없습니다([object.ko.md](object.ko.md) 참고). `any`는 이 경우를 JSSN에서 표현할 수 있게 하기 위해 존재하지만, 이 경우에만 국한되지 않고 타입이 필요한 모든 곳에서 사용할 수 있습니다.
